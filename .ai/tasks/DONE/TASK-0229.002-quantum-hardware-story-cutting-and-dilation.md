## Why
The challenge's §4.2 asks for **coarse-graining with proof that compression
retains the topological signal**, and for **noise resilience**. We answered the
first with a measured negative ([[TASK-0182]]: retention Jaccard 0.00–0.18) and
the second empirically — but the challenge cites two specific methods we never
addressed at all:

- **[10] circuit cutting / quasiprobability simulation of non-local channels.**
  A paper-level treatment discharges the coarse-graining half of §4.2 *on
  paper*: partition the residue graph, state the sampling overhead, and give
  the resulting resource scaling. We currently have no answer to "how would you
  fit a 704-residue protein on near-term hardware" other than "you can't."
- **[11] SVD/dilation for open-system dynamics.** This is the **missing
  implementation route for ENAQT** — the register measured dephasing-assisted
  transport extensively and never said how it would be realised on hardware.

**Citations verified directly, before writing anything against them**:
- [10] Mitarai & Fujii (2021), *Quantum* 5:388, "Overhead for simulating
  a non-local channel with local channels by quasiprobability sampling"
  — confirmed. Also confirmed the actual overhead scaling this line of
  circuit-cutting work establishes (not assumed from the task file's own
  one-line summary): O(9ⁿ) sampling overhead for *n* cut non-local
  two-qubit gates without inter-subcircuit classical communication,
  reducible to O(4ⁿ) with it.
- [11] Oh, Krogmeier, Schlimgen & Head-Marsden (2024), *ACS Phys Chem Au*
  4(4):393-399, "Singular Value Decomposition Quantum Algorithm for
  Quantum Biology" — confirmed exactly (title/journal/volume/pages), and
  found to be directly on-topic, not just topically adjacent: the paper's
  own worked example is excitonic energy transport through the FMO
  complex — the same physical phenomenon (dephasing-assisted transport)
  as this register's own ENAQT measurements.

**[10] partition scheme + sampling overhead — a real, measured cut
count, not an assumed one.** New `scripts/task0229_002_circuit_cutting_
partition.py`: partitions each mandatory target's actual `H_new`
coupling graph into NISQ-sized islands (target size 14, matching
[[TASK-0182]]'s own ~12-16 qubit NISQ-budget framing) via
`coarse.coarse_grain`'s existing Louvain machinery — reused unmodified,
not re-derived — then counts genuine boundary-crossing coupling edges
using the exact same nonzero-upper-triangular convention `coarse.
trotter_cost` already uses for its own gate-count estimate. Classical
graph analysis only, no circuit built or run, matching this task's own
Out Of Scope.

| Target | Islands (actual) | Max island (qubits) | Cut edges *n* | log₁₀ overhead (9ⁿ) | log₁₀ overhead (4ⁿ) |
|---|---|---|---|---|---|
| KRAS_G12C | 10 | 23 | 235 | 224.2 | 141.5 |
| BCR_ABL1 | 14 | 56 | 344 | 328.3 | 207.1 |
| CARDIAC_MYOSIN | 15 | 98 | 510 | 486.7 | 307.1 |
| MYC_MAX | 9 | 25 | 159 | 151.7 | 95.7 |

Reported in log₁₀ form deliberately — the raw overhead value overflows
a 64-bit float (`9.0**235` raises `OverflowError`) before any
formatting is even attempted, itself informative about the scale
involved. For context stated in the write-up: the observable universe
holds an estimated ~10⁸⁰ atoms; every mandatory-target cell above
exceeds that by 15-400+ orders of magnitude, even in the cheaper (4ⁿ,
classical-communication-assisted) regime.

**Honest caveat on the partition itself, stated not hidden**: Louvain
optimizes modularity, not size-balance — `max_island_qubits` (23-98)
overshoots the ~12-16 NISQ target substantially on the larger targets
(CARDIAC_MYOSIN's biggest island alone is 98 qubits, itself infeasible
before any cutting is even considered). A size-balanced min-cut
algorithm (e.g. METIS-style) would likely reduce this imbalance and
might shift the cut count somewhat — not attempted here (out of this
task's own paper-level scope), and would not change the conclusion: the
overhead is astronomical by 100+ orders of magnitude either way, not a
close call sensitive to a 2x change in *n*.

**[11] dilation route for ENAQT — the one route in the document that
clears the qubit-count bar, precisely caveated.** Ref [11]'s own stated
resource requirements: 1 ancilla qubit *independent of system size* (a
real, disclosed advantage over Stinespring dilation, whose ancilla count
scales with the channel's Kraus rank), gate count O(4^d) with *d* the
*system*-qubit count. Their own worked FMO example needs only 8 total
qubits for a 7-site system — because *d* there is an amplitude/log-scale
encoded register over site-basis states (⌈log₂ 7⌉ = 3 system qubits + a
few for the dilation), not one qubit per site.

**The catch, worked through rather than glossed over**: [[TASK-0182]]'s
entire resource table — and every propagator/observable in this
register — uses one qubit per residue, matching the CTQW-on-a-graph
convention this whole project is built on. Ref [11]'s small qubit counts
come from a *structurally different* base encoding this project has
never built or costed. Projected honestly under that alternative
encoding (a projection using ref [11]'s own complexity formula applied
to this project's own N, explicitly labelled as unbuilt): *d* ≈
⌈log₂ N⌉ ≈ 9-10 system qubits for N up to 704, +1 ancilla = 10-11 total
qubits, O(4^d) ≈ 1.0×10⁵-1.0×10⁶ gates. This is the first genuinely
NISQ-plausible *qubit count* found anywhere in this register — a large
but non-astronomical gate count, not an "impossible" one.
