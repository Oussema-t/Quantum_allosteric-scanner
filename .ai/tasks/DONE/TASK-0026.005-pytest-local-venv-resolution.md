# TASK-0026.005 pytest_local.py doesn't resolve a repo-local venv (subtask of TASK-0026)

## Context

- ID: TASK-0026.005
- Title: `.ai/tools/pytest_local.py` invokes `sys.executable` unconditionally,
  so it silently fails in any environment where the interpreter running the
  wrapper itself isn't the one with `numpy`/`pytest`/etc. installed
- Status: Done
- Owner: Toolsmith
- Claimed By: —
- Claimed At: —
- Parent: [TASK-0026](../TODO/TASK-0026-capability-runner-recovery.md) (TODO)
  — sibling of [TASK-0026.004](../IN_PROGRESS/TASK-0026.004-test-execution-self-verification.md)
  (In Progress, currently claimed by a different thread — this is filed as
  a new sibling subtask rather than a TODO line inside that file so it
  doesn't collide with that thread's active edits).
- Source: direct incident, Implementer A thread, 2026-07-09 — asked to
  "rerun the tests" before picking up new work. `python3
  .ai/tools/pytest_local.py backend --json` failed:
  `/usr/bin/python3: No module named pytest`. This repo had no `.venv/` at
  session start; backend deps (`numpy`, `scipy`, etc., see
  `requirements.txt`) plus `pytest` had to be installed into a freshly
  created `.venv/` per `CLAUDE.md`'s own setup instructions. `sys.executable`
  inside `pytest_local.py` resolves to whatever `python3` the *wrapper
  invocation itself* used — in a fresh Bash call with no venv active, that's
  the system interpreter, which has none of these packages. TASK-0026.004's
  own Done section recorded this same wrapper passing all seven presets on
  2026-07-06 in what was presumably a session where the ambient `python3`
  already had the packages (a persistent venv or global install) — so this
  isn't a regression in the wrapper's code, it's an environment assumption
  the wrapper never checks or documents.
- Scope: `.ai/tools/pytest_local.py` only — specifically `run_preset()`'s
  `cmd = [sys.executable, "-m", "pytest", ...]` line. No change to preset
  definitions, `--json` output shape, or any other `.ai/tools/*` script.

## Intent Contract

- Outcome: `pytest_local.py <preset>` works from a cold Bash call (no prior
  `source .venv/bin/activate` in the *same* call, which the Bash tool's
  per-call shell reset makes impossible to rely on anyway --
  `feedback_no_cd_no_echo_chaining` memory / command-hygiene both already
  rule out chaining `source ... && pytest_local.py ...` as one call) in any
  repo checkout that has a `.venv/` built per `CLAUDE.md`'s documented setup
  steps, without the caller needing to know or care which interpreter ends
  up running pytest.
- In Scope:
  - resolve the interpreter in this priority order: (1) `REPO_ROOT/.venv/bin/python3`
    if it exists on disk, (2) fall back to `sys.executable` unchanged
    (today's behavior) if no `.venv/` is present -- so environments that
    already work today (ambient interpreter has the packages) keep working
    identically, and this is purely additive for the common case.
  - if the resolved interpreter still can't import `pytest` (e.g. a `.venv/`
    exists but wasn't `pip install -r requirements.txt`-ed), fail with a
    clear message naming the resolved interpreter path and pointing at
    `CLAUDE.md`'s setup command, instead of the current bare
    `ModuleNotFoundError` traceback text from a subprocess.
  - one-line note in this tool's own module docstring and in
    `.ai/reference/CAPABILITIES.md`'s `repo.test.pytest-local` row
    documenting the resolution order.
- Out Of Scope:
  - auto-creating or auto-installing a `.venv/` if none exists -- that's a
    write/network action (`pip install`) this wrapper shouldn't perform
    silently; surfacing a clear error naming the missing setup step is
    enough (matches this repo's "approval-gated local helpers" philosophy,
    `.ai/reference/LOCAL_AUTOMATION_MANUAL_ENVIRONMENTS.md`).
  - supporting venv locations other than `REPO_ROOT/.venv/` (e.g.
    `virtualenv`-named dirs, `poetry`/`conda` envs) -- `CLAUDE.md`'s own
    documented setup command creates exactly `.venv/`; widen only if a real
    second convention shows up.
  - the Playwright half of TASK-0026.004 -- untouched, unrelated code path.
- Constraints And Invariants:
  - Python stdlib only, no new dependency (matches TASK-0026's blanket
    constraint).
  - must not change behavior for any environment where the ambient
    interpreter already has the packages (i.e. must not break whatever
    environment TASK-0026.004's 2026-07-06 validation ran in, if `.venv/`
    wasn't present there) -- the `.venv/`-first check must degrade to
    exactly today's `sys.executable` line when `.venv/` is absent.
- Planned Validation: from a cold Bash call with no venv-activation in the
  same call, `python3 .ai/tools/pytest_local.py backend --json` against
  this repo's real `.venv/` (already built this session) succeeds with
  `"passed": true`; temporarily rename `.venv/` and confirm the fallback
  path still resolves to `sys.executable` (i.e. reproduces today's error
  message, not a new one) so the "degrades identically when absent"
  constraint is verifiably true, not just asserted.

  validated by code inspection only, not a live run — see Open Questions.
- No change to preset definitions, `--json` output shape, or any other
  `.ai/tools/*` script.
