## Why this matters — this is the experiment that settles an open dispute

[[TASK-0158]] found the project's historical scattered null anti-conservative
(4.8× at α=0.05) and replaced it with a compact k-NN ball. The external panel
review reproduced the 4.8× figure independently (5.2×) but found the
**replacement over-corrects**: on a synthetic surface-lining pocket geometry,
actual α under the ball null was 0.013 against a nominal 0.05 — roughly 4×
too conservative, at a 2–2.5× cost in power. The ball is ~30% more compact
than a surface patch and is correctly calibrated *only* in the limit where a
real pocket is a solid ball.

That finding is currently **synthetic-only**. This task measures it on real
apo topologies with the project's own machinery, and it decides something
consequential: [[TASK-0158]]'s corrected re-run removed `dcc_low`'s
Bonferroni significance on both CARDIAC_MYOSIN (p 0.000→0.060) and PTP1B
(p 0.001→0.019), firing the pre-registered falsification statement and
producing [[TASK-0161]]'s "zero positives program-wide" headline. **If the
ball null is measurably over-conservative on real data, that falsification
fired against a mis-specified alternative and the headline needs correcting.**

Note the diagnostic already in hand: [[TASK-0161]] observed *fewer* positives
than α=0.05 chance predicts (0 observed vs ~11.3 expected across 226 cells)
and read it as strength. **A test that produces fewer positives than chance
is, by definition, not operating at its nominal level.** That observation was
already the evidence; this task turns it into a measurement.

## Intent Contract

- Outcome: a measured end-to-end false-positive rate per (target × observable
  × null specification), against a nominal α, with binomial CIs — plus a
  one-line verdict on which null specification is calibrated on real data.
- Why required, not assumed: the pipeline's actual α has never been measured
  end-to-end at protein scale; every p-value the project reports is
  conditioned on a null whose calibration on real, spatially autocorrelated
  score fields is unverified in either direction.

- In Scope:
  - `strength=0` (bit-identical `W`, asserted per [[TASK-0167.001]]'s
    identity test), ≥500 randomly placed distal compact patches per (target,
    observable), each pushed through the **complete** certification chain
    used in .002.
  - The same 3 null specifications: scattered / compact-ball /
    Rg-matched-to-the-drawn-patch.
  - **The calibration statistic itself, and this is the generalizable part:**
    for each null, check whether the *real* labelled pocket's own geometry
    statistic (radius of gyration; secondarily graph spread and mean
    pairwise hop) lies inside the null draws' distribution of that same
    statistic. Report the percentile. A null whose draws are systematically
    more compact than the real pocket is over-conservative; systematically
    less compact, anti-conservative. **This is a direct, cheap, and
    completely general admissibility test that costs one function.**
  - Measure and report the real pocket Rg for all 7 pocket-scoreable targets
    — a number the project needs anyway and does not currently have recorded.

- Out Of Scope:
  - Changing any null in `RESULTS.md`'s already-reported cells. This task
    *measures*; the re-run of affected cells is a separate follow-up, filed
    once this task's verdict is known (do not pre-file the correction — that
    presumes the outcome).
  - Inventing a new null draw. If all three are miscalibrated, that is the
    finding and the fix is a separate task.
  - The LOD — .002.

- Constraints And Invariants:
  - Patches drawn under the same admission criteria as .002's planted patches
    (distal, floor-AUC ≤ 0.5 pre-draw) so the two experiments are directly
    comparable. A specificity measured on easy patches does not bound the LOD
    measured on hard ones.
  - No gate is relaxed, skipped, or reordered.
  - `strength=0` must be verified bit-identical, not assumed — otherwise this
    is not a specificity measurement.

- Planned Validation:
  - **Concordance:** this task's false-positive rate must match .002's
    `strength=0` row within Monte Carlo error. Two independent routes; a
    disagreement is a bug.
  - **Positive control on the calibration statistic itself:** a deliberately
    scattered draw must register as anti-conservative and a deliberately
    over-compact draw (e.g. size/2 nearest neighbours) as over-conservative.
    If the statistic cannot detect miscalibration it is known to have, it
    cannot certify calibration it claims to find.

**A real, documented optimization over naively copying .002's per-cell
loop, stated not hidden**: at `strength=0`, `plant_channel` returns `W0`
bit-identical (re-verified directly here, not assumed — asserted before
any scoring), so the score is one fixed vector per target. The
permutation null for "scattered"/"compact" is also patch-independent
(the draw depends only on `pocket_size`, fixed at 14, never on which
patch is tested) — precomputed once per target, reused across all 500
test patches, instead of redrawn 500 times. Only "matched" genuinely
depends on the tested patch's own Rg and is redrawn per patch (at a
documented, reduced 200 replicates rather than 1000 — the dominant
remaining cost).

### Part A — measured false-positive rate, 3 mandatory targets, 500 distal patches each

| Target | Scattered α̂ (95% CI) | Compact α̂ (95% CI) | Matched α̂ (95% CI) |
|---|---|---|---|
| KRAS_G12C | 0.000 [0, 0.008] | 0.000 [0, 0.008] | 0.000 [0, 0.008] |
| BCR_ABL1 | **0.188** [0.156, 0.225] | 0.000 [0, 0.008] | 0.002 [0.0004, 0.011] |
| CARDIAC_MYOSIN | 0.018 [0.009, 0.034] | 0.000 [0, 0.008] | 0.000 [0, 0.008] |

(Nominal α = 0.05 throughout.) **Real, decisive finding**: the scattered
null is confirmed anti-conservative on BCR_ABL1 specifically — 18.8%
measured false-positive rate against a 5% nominal bar, a ~3.8× inflation,
directly reproducing the mechanism [[TASK-0158]] found and fixed. **The
compact and Rg-matched nulls show no anti-conservative bias anywhere —
if anything they are conservative** (α̂ ≤ 0.2% on every cell where a
result was measurable). This is on `transmission_from_source(E=0)` on a
weighted `hamiltonians.laplacian` — the one plant-sensitive observable
this program's positive-control apparatus can actually exercise
([[TASK-0167.001]]'s own finding that `H_new`/`dcc_low`/`ctqw` are
plant-blind); it is **not** a re-test of the external review's own
`dcc_low`-specific synthetic audit, and is not claimed as one.

### Part B — the calibration statistic: real pocket Rg vs. each null's own draw distribution, all 7 pocket-scoreable targets

| Target | Real pocket Rg | Scattered null: real-pocket percentile | Compact null: real-pocket percentile |
|---|---|---|---|
| KRAS_G12C | 8.49 | 0.0 | 1.000 |
| BCR_ABL1 | 7.45 | 0.0 | 0.968 |
| CARDIAC_MYOSIN | 9.63 | 0.0 | 1.000 |
| PTP1B | 7.97 | 0.0 | 1.000 |
| GLUCOKINASE | 8.69 | 0.0 | 1.000 |
| CASPASE1 | 6.42 | 0.0 | 0.997 |
| CASPASE7 | 10.84 | 0.0 | 1.000 |

**This is the decisive, general, observable-independent confirmation of
the external review's over-correction concern — measured directly on
real data, not a synthetic construction.** The scattered null's own
draws are, without exception, far less compact than any real pocket
(percentile 0.0 on all 7 targets — the real pocket sits below the
*minimum* of 2000 scattered draws' own Rg every time). **The compact
null's own draws are, almost without exception, more compact than the
real pocket** (percentile ≥0.97 on all 7, exactly 1.000 on 5/7) — real
pockets are systematically *more dispersed* than a pure k-NN ball,
confirming the external review's own synthetic finding ("the ball is
~30% more compact than a surface patch") generalizes to every real
target in this project's own register, not just the review's own
constructed case.

### Part C — positive control on the calibration statistic itself

Reference Rg = 5.98 (median of compact draws, KRAS_G12C topology). A
deliberately scattered draw registers at percentile 0.0 (correctly
anti-conservative-direction); a deliberately over-compact draw
(half-size k-NN) registers at percentile 1.0 (correctly
over-conservative-direction). The statistic detects both known-bad
extremes as designed — it can certify calibration it claims to find.

### Concordance with [[TASK-0167.002]]'s own `strength=0` row — checked, no disagreement

.002's own 20-seed `strength=0` cells: KRAS_G12C 0/20 all 3 nulls,
BCR_ABL1 1/20 scattered / 0/20 compact / 0/20 matched, CARDIAC_MYOSIN
0/20 all 3 nulls. Every one of these is statistically consistent with
this task's own 500-patch measurement (e.g. BCR_ABL1 scattered: a 20-draw
binomial sample with true rate 0.188 has ~1.4% chance of landing at
exactly 1/20 — unlikely but not a disagreement, and well inside a 95%
prediction interval). **No bug found in either measurement** — the two
routes agree; this task's own larger sample simply resolves BCR_ABL1's
scattered-null anti-conservatism with enough precision to be decisive
(20 samples cannot distinguish a 5% true rate from an 18.8% one; 500 can).

### Verdict on the null-calibration dispute

**Compact and Rg-matched nulls are the calibrated choice on real data —
not over-conservative in the sense of producing few false positives
(Part A), but real pockets are measurably more dispersed than either
draw's own geometry (Part B).** Both are true simultaneously: a null
built from a systematically-too-compact patch population produces very
few false certifications (conservative in the α sense) *and* is a poor
geometric model of the actual answer key (over-compact in the
calibration-statistic sense) — the two are the same underlying fact
read two ways, not a contradiction. **Recommend the calibration
statistic itself (Part B's own percentile check) become
`INVARIANCE_PROTOCOL.md`'s fourth class, CALIBRATION, per the external
review's own suggestion** — it is now validated on real data across all
7 targets, not just proposed.
