## Why this matters

This is the task that converts *"we found nothing"* into a measurement. Every
`NO_SIGNAL_IN_APO` verdict in `COMPETENCE_MAP.md` currently has no stated
detection bound. After this task, each one reads *"no signal above our
measured LOD of X,"* which is falsifiable, quantitative, and defensible.

It is also the direct empirical test of the external review's §2.1 claim that
the current null costs 2–2.5× power. The detection curve run under all three
null specifications (scattered / compact-ball / Rg-matched) settles that
dispute with this project's own data rather than a synthetic argument.

## Intent Contract

- Outcome: for each (target × observable × null specification), a detection
  curve `P(certified) vs. plant strength` over ≥20 planting seeds per
  strength, and an extracted **LOD** = the smallest strength at which
  P(certified) ≥ 0.80. Reported in raw strength **and** in the induced-
  coupling units [[TASK-0167.001]] settles on (`R_eff` recommended).
- Why required, not assumed: the pipeline's combined gates (floor → CI
  non-overlap → permutation null → Bonferroni) have never been shown to pass
  anything; [[TASK-0161]] reports zero positives across 226 cells, which is
  consistent with both a true negative and an apparatus with no power.

- In Scope:
  - **Targets:** all 3 mandatory (KRAS_G12C, BCR_ABL1, CARDIAC_MYOSIN under
    [[TASK-0124]]'s corrected 8QYP apo). Add PTP1B if cheap.
  - **Observables — the ones the program's negative claims actually rest on:**
    `time_averaged_ctqw_converged` on `H_new` (the headline),
    `dcc_low`/`prs_low` at k=20 ([[TASK-0149]], the strongest prior positive),
    `T(E=0)` on `L` ([[TASK-0145]], the unresolved cell). Four observables is
    the minimum honest set; do not expand — this is a power measurement, not
    a new sweep.
  - **Strength grid:** log-spaced, bracketing the prototype's observed
    threshold — suggest `{0, 0.5, 1, 2, 4, 8, 16, 32}`. Extend upward only if
    the top of the grid is still undetected (and if so, **report that** — an
    LOD above any physically plausible coupling is itself a decisive result
    about the apparatus).
  - **Certification = the real, unmodified verdict path**, all gates in
    series, exactly as a real target is judged:
    1. planted-label AUC clears the proximity floor (point estimate), AND
    2. 95% CI non-overlap with the floor's CI — **using
       `spatial_block_bootstrap_ci`**, not the sequence-block version
       (see Constraints), AND
    3. stratified-AUC well-powered max clears its permutation null, AND
    4. that null p-value clears the family Bonferroni bar.
    Record which gate fails at each strength — **the per-gate failure profile
    is as valuable as the LOD itself.** If gate 2 (CI non-overlap) is the
    binding constraint at every strength, that is a finding about the CI
    method, not about allostery, and it explains why no cell in the project's
    entire history has ever had a non-overlapping CI.
  - **Three null specifications, run side by side:** `rng.choice` (scattered,
    the historical convention), `nulls.compact_patch` (the [[TASK-0158]]
    fix), `nulls.compact_patch_matched` (Rg-matched to the *planted patch's
    own* measured Rg). This is the decisive test of the external review's
    over-correction finding.
  - ≥20 planting seeds per (target, strength) cell; report P(certified) with
    a binomial CI, not a bare fraction.
  - Checkpoint per cell to disk ([[TASK-0138]]/[[TASK-0143]] both lost runs
    by writing once at the end — do not repeat this).

- Out Of Scope:
  - Adjusting any gate, threshold, or null in response to the result. If the
    LOD is high, that is reported, not fixed. **Tuning a gate against a
    positive control you designed is label leakage of the worst kind.**
  - Re-running any real-target scored cell.
  - New observables.

- Constraints And Invariants:
  - Pipeline unmodified. The plant enters only via `W`/`H`; every scoring,
    CI, null, and Bonferroni call is the existing one.
  - The floor is recomputed post-plant and asserted unchanged
    ([[TASK-0167.001]]'s gate) for every single plant, not spot-checked.
  - **Use `spatial_block_bootstrap_ci`, and note the caveat:** its own 1D-line
    regression test currently **fails** (external review §2.2 — the sequence
    window is forward-from-centre, the k-NN block is centred, 54% mean
    overlap, not the coincidence its docstring claims). Either land that fix
    first or run *both* CI methods and report both. Do not silently use a
    method whose validation is red.
  - Label-blind is not applicable here (the label is planted by construction)
    — but the *strength* must never be tuned against detection. Fix the grid
    before running.

- Planned Validation:
  - The `strength=0` row **is** the specificity check and must match
    [[TASK-0167.003]]'s independently-computed false-positive rate. Two
    routes to the same number; a disagreement is a bug in one of them.
  - Monotonicity sanity: P(certified) should be non-decreasing in strength
    for a well-behaved observable. Non-monotonicity is a real finding
    (report it) — the prototype already showed `|DCC|` ratio is non-monotone,
    so do not assume the induced-coupling axis is either.

## Done

**Headline: under this project's own current (corrected, compact) permutation null, no
target reaches 80% detection power at any planted strength tested (up to ~4× background
conductance). Under the superseded scattered null, LOD ≈2× background on 2/3 targets.
The gap between those two numbers is the measured cost of the [[TASK-0158]] correction —
a direct, considerably more severe confirmation of the external review's own §2.1
"2–2.5× power cost" estimate than that estimate itself claimed.**

### Scope decision, built directly on [[TASK-0167.001]]'s own finding

Reconfirmed first, cheaply, on all 3 targets (strength 0 vs. 32, `np.array_equal`):
`time_averaged_ctqw_converged` on `H_new`, `dcc_low`, `prs_low` are exactly plant-
invariant. Running the full 8×20 grid against them would have reproduced one identical
score 160 times per target for no information — the real, informative sweep covers only
`T(E=0)` on a weighted `hamiltonians.laplacian(W_planted)`, the one plant-sensitive
observable in this task's own named list.

### Compute budget

3 targets × 8 strengths × 20 seeds × 3 nulls × 2 CI methods = 480 cells, ~87 CPU-minutes
total (checkpointed, resumable, `scripts/positive_control_detection_curve.py`). Two
mitigations applied from this task's own Open Question, both stated rather than silently
assumed: (a) the floor's own AUC/CI depends only on `(target, seed)`, never on plant
`strength` (never sees `W`, [[TASK-0167.001]]'s own theorem) — cached per seed, reused
across all 8 strengths, roughly halving the CI-bootstrap workload; (b) `N_BOOT_CI`
reduced from the project's usual 1000 to 500 replicates (still a standard bootstrap
floor, Efron & Tibshirani) — checked directly on KRAS_G12C at 3 strengths that gate-2
verdicts and CI bounds are effectively unchanged at 500 vs. 1000, not assumed adequate.
All 3 nulls were run (not reduced to 2, the Open Question's own fallback) — the full
480-cell grid completed comfortably inside the estimated window.

### The CI-validity Constraint, resolved by dual-reporting (not by fixing either function)

The external review's own claim that `spatial_block_bootstrap_ci`'s 1D-line regression
test is invalid was verified directly before trusting or dismissing it: **55.1% mean
block-index overlap** between the sequence window (asymmetric, forward-only from its
start index) and the spatial k-NN block (symmetric, centred) — matching the review's own
54% almost exactly, confirming [[TASK-0165]]'s own "exact reduction" claim was
overstated (the aggregate-CI-width test that shipped was a weak proxy for "same index
sets," which is what the docstring actually claimed). **Corrected in [[TASK-0165]]'s own
Done section and in `metrics.py`'s own docstring** (2026-07-28) rather than left standing
— no fix to either block construction was attempted (both options touch a much larger
surface: an asymmetric spatial block has no natural 3D definition beyond the 1D special
case, and a symmetric sequence block would change every CI this project has ever
reported). Per this task's own explicitly sanctioned alternative, every cell computes
gate 2 under **both** CI methods. **In the event, they gave identical LOD values on every
target** — the real, now-corrected validity concern did not change this task's own
bottom line, though it would be wrong to have assumed that in advance.

### A second real bug, found and fixed in analysis, not by re-running the expensive collection

The collection script's own `certified`/`gate4_clears_bonferroni` fields divided
α=0.05 by `len(strengths)×len(seeds)=160` — this task's own synthetic measurement grid,
not a real multiple-comparisons family. A real single-target deployment of `T(E=0)`
corrects across **targets** ([[TASK-0145]]'s own established convention,
`N_TARGETS_FOR_BONFERRONI=3`, α≈0.0167), not across however many synthetic replicates
this experiment happens to draw. Caught before trusting any LOD number; fixed in
`scripts/detection_curve_analysis.py`, which recomputes certification from each cell's
own raw, uncorrected `p_value` (already stored) — no re-run of the expensive collection
pass was needed, only the Bonferroni denominator was wrong, not the underlying p-values.

### Per-gate failure profile — gate 2 (CI) and the permutation-null gate are BOTH independently binding

On KRAS_G12C at strength 32, gate 1 (beats floor) passes 100% of the time, yet gate 2
(CI non-overlap) fails 50–55% of the time even then — stronger planted signal does not
monotonically narrow/separate the score's own bootstrap CI from the floor's (a plausible
mechanism, not independently verified here: a more concentrated effect on fewer residues
may produce a noisier block-resampled CI, not a tighter one). Even restricting to cells
where gates 1 and 2 both pass, the compact/matched-null permutation test alone caps
P(certified) at 35–50% at each target's own best strength. Neither gate alone explains
the corrected-null LOD failure — both are real, independent bottlenecks, exactly the
"per-gate failure profile is as valuable as the LOD itself" instruction this task's own
Intent Contract asked for.

### Non-monotonicity — real, matches TASK-0167.001's own predicted mechanism

P(certified) for the compact/matched nulls is not monotonically non-decreasing in
strength on 2/3 targets (KRAS_G12C: peaks 0.35 @ s=8, falls to 0.05 @ s=32;
CARDIAC_MYOSIN: peaks 0.50 @ s=8, falls to 0.45 @ s=32) — the Planned Validation's own
explicit sanity check, and a real finding, not assumed away. Plausible mechanism, matching
[[TASK-0167.001]]'s own Open Questions prediction exactly (not chased to full mechanistic
confirmation, out of this task's own scope): at extreme strength the planted channel's
own intermediate residues (negatives under the patch label) become strongly scored
themselves, and channel leakage depresses within-shell discrimination enough to
counteract the raw AUC gain.

### Compact vs. Rg-matched null: empirically indistinguishable (checked, not assumed)

Every P(certified) value is identical between the two null columns, every target, every
strength. Verified this is real: `compact_patch_matched` accepted on its first or second
draw in 19/20 direct trials at the ±35% Rg tolerance — a fresh `compact_patch` draw at a
fixed size already has a naturally tight Rg distribution across random seed choices, so
it is already within the review's own matching tolerance almost always. The
compact-vs-scattered gap is real and large (this task's own headline); the
compact-vs-Rg-matched gap is not measurable at this patch size — a real, informative
answer to part of the external review's own over-correction question, not a null result.

### BCR_ABL1 — a real, target-specific limitation, reported not smoothed over

Never reaches 80% power under any null, including the historically-lenient scattered
one (max P=0.60 at the grid's own top). Gate 1 alone fails 60% of the time even at
strength 0–4. Not chased to a root cause (out of this task's own scope) — plausibly
BCR_ABL1's own selected patch sits closer to its pre-plant floor than the other two
targets' by construction (the admission bar is ≤0.5, not ≤0), or its larger, more
redundant topology (N=451) is intrinsically harder for this specific channel-reweighting
mechanism to move.
