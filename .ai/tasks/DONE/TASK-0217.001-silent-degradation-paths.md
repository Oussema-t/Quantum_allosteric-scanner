# TASK-0217.001 Silent degradation paths — helpers that return a value where they should raise

## Context

- ID: TASK-0217.001
- Parent: [[TASK-0217]]
- Status: Done
- **Thread: Implementer A.** Mechanical, mostly grep + targeted reading.
- Owner: Implementer
- Priority: **P0 within the family** — this class produced the single most
  consequential defect found ([[TASK-0216]]: 9 of 13 targets seeded at graph
  hubs) and it is the cheapest to sweep.

## The class

A helper that cannot do what it was asked, and **returns a plausible value
instead of refusing**. The caller has no way to know. Two confirmed instances,
both in the core label pipeline:

1. **`labels.functional_indices`** — when no `func_ligand` code matched, it
   returned `np.argsort(-degree)[:5]` tagged `"top-degree fallback"`, silently.
   Fired on 9 of 13 register targets. Every active-site-seeded observable on
   those targets is a function of graph degree, and `degree_centrality` is
   simultaneously one of the three proximity-floor baselines — so observable
   and floor shared a construction. Fixed in [[TASK-0216]] (now warns).
2. **Heavy-atom index misalignment** — `functional_indices`/`holo_pocket_mask`
   return indices in whichever array's heavy-atom index they were handed.
   Passing holo's into an apo-sized mask is silently wrong whenever the two
   differ in length, which is **every** register target. It only crashes when
   holo is *longer*; when holo is shorter it silently misaligns.

## Retrospective test — run before trusting this audit on anything new

The audit must independently rediscover **both** defects above from a clean
start. If the method cannot find the two bugs that motivated it, it will not
find the unknown ones.

## Intent Contract

- Outcome: an enumeration of every fallback/degradation branch in
  `src/allostery/` (and `scripts/` helpers that other scripts import), each
  classified **safe** (documented, loud, or genuinely harmless) or **unsafe**
  (silent substitution a caller could mistake for a real answer); plus a
  permanent guard for each unsafe one.
- In Scope:
  - Grep for the shape: `except ... : return`, `if not X: return <default>`,
    `or <fallback>`, bare `warnings.warn` followed by a degraded return, and
    any function whose docstring says "falls back" / "approximation" /
    "otherwise".
  - For each: does the caller receive anything distinguishing the degraded
    result from a real one? A returned provenance string the caller ignores
    counts as **silent** — `functional_indices` did return `"top-degree
    fallback"` and every caller dropped it on the floor.
  - **Array-correspondence check**: every function taking two structures'
    arrays (apo/holo) and returning indices — assert which space the indices
    live in, and that the arrays correspond. Length equality is a cheap proxy.
  - Prefer raising, or warning loudly, over returning a plausible default.
- Out Of Scope:
  - Rewriting the science. Guards only.
  - Statistical helpers (floors, nulls, LOD) — repeatedly checked, clean.
- Constraints:
  - **Report the denominator.** "We audited N helpers, M were unsafe" is a
    different claim from "we found M bugs," and the parent task requires it.
  - Any behaviour change to a shared helper must keep the full suite green
    (1146 passing at time of filing) and be additive where possible.
- Planned Validation: the retrospective test above; plus, for each new guard,
  demonstrate it fires on a constructed bad input before it passes on real data.

### The defect: `functional_indices` returned indices in the wrong structure's space

`labels.py::build_labels` (and 3 other call sites: `consensus_labels.py`,
`scripts/task0178_response_coupling.py`, `scripts/task0216_score_new_pairs.py`)
call `functional_indices(apo.coords, holo.ligand_groups, ..., heavy_atom_coords=holo.heavy_atom_coords, heavy_atom_seq_index=holo.heavy_atom_seq_index)`
to get true heavy-atom contact geometry against the func-ligand (which only
exists in holo). `heavy_atom_seq_index` indexes into **holo's own** residue
array (built via `protein_heavy_atoms_by_residue(holo_struct, chains,
holo.resnums)`), but the returned indices were used directly as **apo**-space
indices (`active_site = np.zeros(len(apo.resnums)); active_site[func_idx] =
True`) — silently correct only when apo and holo happen to share identical
numbering, and silently wrong otherwise. `holo_pocket_mask`, right next to
it in the same file, already does this translation correctly via
Needleman-Wunsch — this was an inconsistency within the module, not a
uniformly-applied design.

**Confirmed and quantified on real targets** (`n_apo`/`n_holo`/start-offset
from `clean_from_config`, both roles):

**10 of 13 real targets exposed** (any target where `func_ligand` resolves
to a real ligand contact, not the fallback) — including both KRAS_G12C and
BCR_ABL1, 2 of the register's 3 mandatory targets. Directly demonstrated
wrong on KRAS_G12C and BCR_ABL1 before fixing (misapplied indices landed on
the wrong residues by exactly the numbering offset — e.g. KRAS_G12C's
"active site" residue 12 should have been residue 11).

**Consequence beyond the CTQW seed, found while quantifying blast radius**:
`active_site` also gates `SEAM-0003`'s pocket-label exclusion
(`pocket = pocket_raw & ~active_site & ~terminal`) — so the bug affected not
only which residues seed the quantum walk, but the **ground-truth pocket
label** nearly every AUC in this register is scored against, on the same 10
targets. Measured directly: KRAS_G12C's pocket label changed from 18 to 17
residues after the fix, and `tests/test_fpocket_pin.py`'s own golden-value
regression test (whose pinned AUC is computed via `build_labels`) shifted
from **0.7910 to 0.8210** — a real, legitimate, ~0.03 AUC change on the
register's single most-cited classical-comparator number, not the binary-
drift class of change [[TASK-0206]] diagnosed for that same test. Handled
per this subtask's own scope boundary (guards only, no re-scoring the
register): marked `xfail` with a dated, explicit reason rather than
silently re-pinned or left as an unexplained failure — re-pinning (and
re-scoring anything else that reads `build_labels`' `pocket` on these 10
targets) is a real, load-bearing follow-up this subtask does not own.

### The fix

`labels.functional_indices` gained two optional, additive parameters:
`heavy_atom_resnames`/`coords_resnames`. Omit both (unchanged default) for
the legitimate same-structure case (a single structure's own full-atom data
used for better-than-Cα contact geometry on itself — already covered by
`test_protocol.py::test_get_functional_indices_forwards_heavy_atom_params`,
still green, untouched). Supply both for the cross-structure case — the
function then translates the result into `coords`' own space via the same
Needleman-Wunsch correspondence `holo_pocket_mask` already uses, before
returning. Supplying `heavy_atom_coords` cross-structure **without** the
resname pair now raises (a partial safety net catches the case where the
indices are provably out of `coords`' range; the resname-pair path is the
real fix and required for the shorter/equal-length silent case). All 4 real
call sites updated to pass the correspondence.

Two new tests in `tests/test_labels.py`
(`test_cross_structure_heavy_atoms_translated_to_coords_space`,
`test_cross_structure_heavy_atoms_without_resnames_raises`) demonstrate the
guard fires on a constructed bad input and the translation lands correctly,
per this task's own Planned Validation.

### A discrepancy found, not resolved

counts describe materially different register states.
