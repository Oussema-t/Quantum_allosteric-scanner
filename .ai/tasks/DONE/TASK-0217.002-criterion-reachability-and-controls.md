## The class

A pre-registered criterion that **cannot return one of its own outcomes**, so
the result was determined before any data existed. Three confirmed:

1. **[[TASK-0204]] D1** — `opt_rate > (1.0 if greedy_hit else 0.0)`.
   `opt_rate` is a fraction of 8 trials, max 1.0. On any greedy-hit target the
   bar was unattainable; a perfect 8/8 returned `False`. The pass bar required
   2/2 targets and one target's greedy hit, so criterion #1 was
   unfalsifiable-positive for the whole run before a trial was scored.
2. **[[TASK-0208]] V1** — the frustration signature required `joint < 0`, but
   transplanting rigid holo rotamers onto an apo backbone always clashes, so
   every `joint` was large and positive (+23 to +115). Post-transplant
   relaxation later removed ~97% of that energy.
3. **[[TASK-0189]]** — Bonferroni family of 160 gave α = 3.1e-4 while the
   permutation floor was `1/n_reps` = 1e-3. The gate could only fire at
   `p == 0` exactly.

**And the sibling failure, same root:** a criterion whose *negative* outcome is
uninformative because no positive control establishes the apparatus could
detect a true positive at all ([[TASK-0204]] D2 — only the apo was scored,
where a cryptic pocket is closed by definition).

**New finding**: `scripts/fpocket_conditional_analysis.py` — `FAMILY_SIZE
= 3 * len(TARGETS) * 2` auto-scales with the target list (the script's own
comment already names this as guarding against [[TASK-0189]]'s family-drift
defect), but nothing checked the other half of that same lesson: as
`TARGETS` grows, `ALPHA = 0.05/FAMILY_SIZE` shrinks toward
`1/N_PERM_REPS = 1e-3`. **Currently reachable** (`ALPHA=0.05/30=1.667e-3`
at today's 5-target `TARGETS` list, confirmed by calling the guard
directly, not assumed) **but at only ~60% of the 1/n_reps floor** — one
more target added to this script (this register has already grown its
`TARGETS` list once, [[TASK-0203]], and [[TASK-0214]]/[[TASK-0215]] just
showed 6 more valid instances exist to draw from) would push `FAMILY_SIZE`
to 36+ and cross into the exact unreachable-gate defect [[TASK-0189]]
already found and fixed elsewhere, silently. **Not a live defect — no
past verdict is affected** (the gate has always been reachable at every
`TARGETS` length actually run) — a latent one, caught before it could fire.
**Fixed**: `assert_gate_reachable(ALPHA, family_size=1, n_reps=N_PERM_REPS)`
called at the top of `main()`, matching the exact pattern
`zero_plant_specificity_analysis.py` already established — verified to
return `True` (reachable) at the current `TARGETS` length without
re-running any part of the actual analysis (Out Of Scope), and will now
raise loudly instead of silently truncating if `TARGETS` grows past the
point where it stops being true.
