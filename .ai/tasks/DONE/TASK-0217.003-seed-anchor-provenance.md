## Why this exists as a separate subtask

[[TASK-0216]] found and fixed the mechanism (9 of 13 targets seeded at the
top-5 highest-degree residues) and settled the one cell that mattered most:
**PTP1B's `dcc_low` positive does not survive the corrected seed** —
p 0.00275 → 0.567, AUC 1.000 → 0.598, no `k` surviving at any level. The
register's only positive was an artifact of the fallback seed.

What remains is propagation, and it is larger than one cell, because the seed
enters in **three** places, not one:

1. `source` — the observable's own seed argument.
2. `shells` — `-hop_from_seed(source)`, the stratification the
   well-powered-max AUC is taken over. A different seed changes which shells
   exist and which residues fall in them.
3. `pocket` — `build_labels` assembles `pocket_raw & ~active_site & ~terminal`,
   so a different active site excludes different residues from the answer key.

Any result on a fallback target is therefore affected in the score, the
stratification, **and** the label — not just the seed.

**A real discrepancy found and resolved en route**: [[TASK-0216]]'s own two
scripts disagree on PTP1B's "real seed" pocket size (4 vs. 14 residues)
because one (`task0216_ptp1b_real_seed.py`) only attaches heavy-atom contact
geometry when `len(apo.resnums) == len(holo.resnums)` — false for PTP1B
(298 vs. 282) — and silently falls back to the weaker Cα-only
approximation, while the other (`task0216_task0201_rerun_real_seed.py`, via
`run_challenge._load_apo_holo`) attaches it unconditionally, matching
[[TASK-0201]]'s own original methodology and `labels.py`'s own documented
heavy-atom-preferred convention. The 14-residue number is the comparable
one; my own first independent-verification attempt initially reproduced the
4-residue number by accident (following the wrong script's own
construction) before this was caught and corrected.

### UniProt-before-top-degree — decided yes, and implemented

`backend/active_site.py::detect_active_site` resolves a real, biologically
correct active site for all 3 remaining fallback targets (PTP1B: Cys215 +
P-loop, 9 residues; CASPASE1/CASPASE7: their Cys/His catalytic dyads, 2
residues each). Implemented as a new tier in `labels.functional_indices`,
between `func_ligand` contact and the top-degree fallback: a static, curated
`active_site_uniprot` field added to `targets.yaml` for these 3 targets
(pre-computed from `detect_active_site`'s own output, **not** imported at
runtime — `labels.py` must not import `backend/`, a live FastAPI service,
per [[TASK-0018]]'s independence boundary; "port, don't import" is this
module's own standing convention). `functional_indices` gained a new
`coords_resnums` parameter to map the curated resnums onto the caller's own
array; `build_labels`/`consensus_labels.py` updated to pass it. **Confirmed:
all 3 targets now resolve `provenance="active_site_uniprot"` with zero
warnings** — this closes the fallback-tier failure mode permanently for
every future run on these targets, not just a one-off patch.
