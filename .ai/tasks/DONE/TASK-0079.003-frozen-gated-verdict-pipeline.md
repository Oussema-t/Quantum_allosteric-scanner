## Intent Contract

- Outcome: one function, e.g.
  `run_frozen_verdict(target_name, candidates_builder) -> dict`, that:
  1. Enters `protocol.frozen_context({target_name})`.
  2. Calls `protocol.select_frozen_config(candidates_builder,
     target_name)` to pick the winning operator/parameter config —
     candidate construction and scoring both happen inside the gate, per
     `select_frozen_config`'s own contract.
  3. Runs `analysis.py`'s scoring functions (`benchmark`, `ablation`,
     `quantum_vs_classical`, `apo_holo_consistency`) against the winning
     config, still inside the gate.
  4. Calls `protocol.stamp_provenance(...)` on the raw results, still
     inside the gate — the stamp must be issued here, not after exit.
  5. Exits the context, assembles via `.001`'s function, and returns the
     stamped, assembled `results` dict — ready for `report.verdict_template`
     to render as `provenance="frozen"`.
- In Scope:
  - the function above, plus a `diagnostics.classify_failure`/
    `permutation_null` call on the winning config's scores, so a target
    whose result is actually indistinguishable from chance (or worse than
    the floor) is flagged in the assembled results rather than silently
    rendered as a clean verdict — `results["_diagnosis"]` or similar,
    consumed downstream by `.004`'s report assembly.
  - unit tests, synthetic (no network): confirm the function raises
    `LeakageError` if any step inside it is made to read `target_name`'s
    holo/pocket data directly (reuse `select_frozen_config`'s own
    "poisoned builder" test pattern from `test_protocol.py`); confirm the
    returned dict's `"_frozen_stamp"` verifies true via
    `protocol.verify_frozen_stamp`; confirm it composes correctly with
    `.001`'s assembly (once that subtask lands — coordinate ordering, or
    stub the dependency if `.001` isn't done yet, per this repo's
    "narrow the first validation action" convention).
- Out Of Scope: candidate generation itself (which operator/parameter
  combinations to try) — reuse whatever mechanism `select.py`'s own tests
  already establish as a valid candidate shape (`{"H", "source", "t"}`
  dicts); this subtask does not invent a new search space, it wires the
  existing one through the gate correctly.
- Constraints And Invariants: **the single most important invariant in
  this whole task family** — nothing inside step 2-4 above may read
  `target_name`'s true holo/pocket label via any path other than what the
  gate already blocks (i.e. don't accidentally introduce a new
  leakage path while wiring this together; if a step genuinely needs
  data the gate would block, that's a design problem to surface, not
  route around).
- Planned Validation: the leak-blocking unit test above is non-negotiable
  — this subtask is not Done without it passing for real, not just "no
  test happened to trigger it."

## Done

- 2026-07-12, Implementer A. Added `protocol.run_frozen_verdict(target_name,
  candidates_builder, coords, bfactors, source, labels, *, cutoff=10.0,
  alpha=0.3, terminal_fraction=0.05, n_low_modes=10, t_max=15.0,
  n_steps=500, floor_scores=None, holo_H=None, holo_source=None,
  holo_labels=None, apo_idx=None, holo_idx=None, consistency_k=20) ->
  dict` in `protocol.py`, right after `select_frozen_config` (same
  placement precedent as that function — an orchestration layer that
  composes the gate, not pure computation, so it belongs alongside it
  rather than in `analysis.py`/`diagnostics.py`).
- Flow matches the Intent Contract's 5 steps exactly, inside one
  continuous `with frozen_context({target_name}):` block spanning
  selection, all scoring, and the stamp: `select_frozen_config` →
  `benchmark`/`ablation` (always default-parameter — neither accepts an
  external H, confirmed by re-reading `analysis.py` directly, so they can
  never run "against the winning config" regardless of task-file prose;
  `AUC_apo_Hnew_default`/`AUC_apo_H10_baseline` correctly stay
  default-parameter numbers) → `quantum_vs_classical` against the
  *winning candidate's own* `H`/`source` (the only analysis function that
  accepts an H) — its `"ctqw"` AUC becomes `AUC_apo_Hnew_optimised`,
  finally wiring PLAN.md's Sec.8 optimizer number for real → 
  `classify_failure` (`_diagnosis`) → `.001`'s `assemble_verdict_results`
  → `stamp_provenance`, still inside the gate, per the Contract's explicit
  "stamp must be issued here, not after exit."
- `labels` (the target's true pocket mask) is accepted as a plain
  pre-fetched array, never read via a gated accessor inside this
  function — reconciles the Intent Contract's "score inside the gate"
  ordering with `leave_one_protein_out`'s own docstring pattern ("read
  the true label after the with block exits"): the gate here mechanically
  polices `candidates_builder`'s calls through `get_pocket_mask`/etc.,
  not the bits of an already-in-hand array. Verified this reconciliation
  is sound by re-reading `protocol.py`'s own "opt-in firewall... not a
  retroactive lock on labels.py's own direct callers" line before
  committing to the design, not guessed.
- Open Question resolved: `floor_scores` is exposed as an optional
  pass-through kwarg (not hardcoded to always call a specific
  `baselines.py` function inside this pipeline) — keeps this function
  agnostic to *which* baseline a caller picks, matching
  `classify_failure`'s own "caller's choice which baseline" docstring; a
  caller (e.g. `.004`) that wants `BEATS_CHANCE_NOT_FLOOR` exercised for
  real just computes a `baselines.py` score and passes it in.
- Holo-side numbers (`AUC_holo_Hnew_optimised`, `mean_rho_apo_holo`,
  `mean_jacc20`) are computed only if the caller supplies an already-built
  `holo_H` (+ `holo_source`/`holo_labels`/`apo_idx`/`holo_idx`) — this
  function does not invent a holo-H-construction recipe itself, per its
  own Out Of Scope ("does not invent a new search space"); omitted
  entirely, not raised, when absent, matching `assemble_verdict_results`'s
  per-key-optional philosophy.
- Tests: `test_protocol.py::TestRunFrozenVerdict` (10 cases) — poisoned
  candidate-builder raises `LeakageError`; a different-target read inside
