## Intent Contract

- Outcome: one script, e.g.
  `__WORK_IN_PROGRESS__/scripts/run_challenge.py --target KRAS_G12C`,
  that loads the target config (`clean.load_target_config`), fetches/
  cleans the apo+holo structures, runs `.003`'s FROZEN-gated pipeline,
  assembles the connectivity matrix and hit list via `.002`, renders the
  methodological report via `report.verdict_template`, and writes all
  three to a per-target output directory (e.g.
  `__WORK_IN_PROGRESS__/results/<target_name>/`).
- In Scope:
  - CLI argument parsing (`argparse`, stdlib only, matching this
    package's existing dependency discipline).
  - output file format — this subtask's own call, since
    [[TASK-0083]] (the real artifact contract) is explicitly out of
    scope for [[TASK-0079]] and shouldn't be guessed at prematurely.
    Recommend: connectivity matrix as `.npz` (`np.savez`, preserves exact
    float precision, standard for this codebase's numpy-heavy data);
    hit list as `.json` (structured, easy for a future TASK-0083 contract
    to consume); methodological report as plain `.txt` (`verdict_template`
    already returns a formatted string — write it verbatim). Document
    the choice in this file's own Done section, don't leave it implicit.
  - a `--dry-run` or `--target-list` mode that prints which targets would
    run without executing (cheap to add, useful for `.005`'s validation
    pass and later `.081`'s generalization-set run).
  - error handling: a failed target (network fetch failure, a target
    whose diagnosis flags `OPERATOR_DEGENERATE`/`LABEL_SUSPECT`/etc.)
    should not crash the whole run if multiple targets are requested —
    log the failure, continue, and reflect it in the written report
    rather than silently omitting the target's output directory.
- Out Of Scope: the artifact contract itself ([[TASK-0083]]); any
  UI/frontend consumption of these files (`backend/`/`frontend/` per
  TASK-0018's "port, don't cross-import" boundary — this script lives
  entirely in `__WORK_IN_PROGRESS__/`, no `backend/` changes).
- Constraints And Invariants: must call `.003`'s pipeline for the actual
  scoring — must not reimplement any part of the FROZEN-gating inline in
  this script (the whole point of `.003` existing separately is that the
  safety-critical logic is tested in isolation; this script is orchestration
  glue only).
- Planned Validation: a dry-run against a synthetic/mocked target
  (no network) confirming the script's control flow and file-writing
  logic; the real network-backed validation is `.005`'s job, not this
  subtask's.
