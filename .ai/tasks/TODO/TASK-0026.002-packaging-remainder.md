## Intent Contract

- Outcome: the remaining rows in `.ai/reference/CAPABILITIES.md`'s Commit
  Packager set that name `agents-tools/capability-runner.sh` are backed by
  real implementations:
  - `repo.packaging.classify-staged-files` — bucket staged files into
    packaging groups (sorted, deterministic)
  - `repo.packaging.branch-file-list <target>` — list staged files for a
    packaging target (`maintenance`, `cluster`)
  - `repo.packaging.plan-next-commit` — prepare next commit from persisted
    split plan; stages next group, writes commit-message draft, marks group
    done in state under `--apply`
  - `repo.packaging.validate-plan-coverage` — validate plan coverage
    (changedCount/groupCount/plannedCount/missing/extra/ambiguous),
    `--json`, optional `--strict`
  - `repo.packaging.refine-plan` — move an area path prefix into a
    dedicated plan group (`--path-prefix`, destination group metadata,
    optional deferred target branch)
  - `repo.packaging.review-plan-rules` — report coverage, area-cohesion
    conflicts, commit-size floor issues, ambiguous-file status, JSON
  - `repo.packaging.cleanup-plan` — cleanup stale split-plan artifacts and
    commit-message drafts; safe dry-run by default, scoped archive/delete
  - `repo.packaging.mr-big-picture` — generate merge-request summary from
    plan/state (default output `.ai/tasks/mr-big-picture.md`), `--json`
  - `repo.maintenance.behavior-contract-capture` — capture scoped UI
    behavior contract artifacts under `.ai/tasks/contracts/`, supports
    extraction from a task file, `--json`
  - `repo.test.playwright-local` — execute local Playwright TC runs;
    pinned working directory/env (`TS_NODE_PROJECT`, `NODE_OPTIONS`),
    explicit CLI spec/project/grep inputs, strict-allowlist request-file
    mode via `.ai/tasks/playwright-local-run.request.json`
- In Scope: the ten rows above, each matching the behavior already
  documented in `CAPABILITIES.md` (do not invent new flags/fields beyond
  what's already promised there).
- Out Of Scope:
  - `repo.vcs.*` and `repo.packaging.snapshot` — TASK-0026.001.
  - correcting `CAPABILITIES.md` wording for anything left unimplemented —
    TASK-0026.003.
  - if a row turns out to need infrastructure beyond a local script (e.g.
    `repo.test.playwright-local` assumes a Playwright project already
    exists) and that assumption doesn't hold in this repo, do not build
    speculative scaffolding for it — implement the dispatcher contract and
    flag the environment gap in this file's Open Questions instead of
    guessing at a Playwright setup that may not apply here.
- Constraints And Invariants:
  - Python stdlib or POSIX shell only, no new runtime dependency, except
    where a row's documented behavior inherently requires an
    already-present environment-specific tool (e.g. Playwright itself for
    `repo.test.playwright-local` — don't newly introduce it, just wrap
    it if present, and flag clearly if it's absent in this repo).
  - write-scoped rows (`plan-next-commit`, `refine-plan`, `cleanup-plan`,
    `mr-big-picture`, `behavior-contract-capture`) must default to a safe
    / dry-run mode and require an explicit flag (`--apply`, etc.) for any
    actual write, matching what `CAPABILITIES.md` already documents per row.
  - destructive-leaning rows (`cleanup-plan`'s delete action) must not
    delete anything without an explicit, narrow, documented scope.
- Planned Validation: exercise the read-only rows
  (`classify-staged-files`, `branch-file-list`, `validate-plan-coverage`,
  `review-plan-rules`) against this repo's real state first, since they're
  the cheapest correctness check; only then exercise write-scoped rows in
  dry-run mode against a disposable/test plan state, never against
  in-flight TASK-0019 packaging state.
