## Intent Contract

- Outcome: `agents-tools/capability-runner.sh <capability-name> [args]
  [--json]` exists, is executable, and correctly backs these
  `.ai/reference/CAPABILITIES.md` rows:
  - `repo.vcs.current-branch` — read current branch name
  - `repo.vcs.short-status` — read short working-tree status
  - `repo.vcs.staged-diff-stat` — summarize staged diff size
  - `repo.vcs.staged-files` — list staged file paths (deterministic, sorted)
  - `repo.vcs.changed-files` — list complete changed-file set (`--scope
    all|staged`; deterministic, sorted)
  - `repo.packaging.snapshot` — composite over the above (fields include at
    least `branch`, `staged.diffStat`; supports `--include-working-tree`)
- In Scope:
  - the dispatcher itself: argument parsing, capability-name routing,
    shared `--json` output plumbing, non-zero exit on unknown capability
    name or git-command failure.
  - the five `repo.vcs.*` subcommands and the `repo.packaging.snapshot`
    composite, exactly as CAPABILITIES.md currently describes them.
- Out Of Scope:
  - every other `repo.packaging.*` row, `repo.maintenance.*`,
    `repo.test.playwright-local` — TASK-0026.002.
  - correcting CAPABILITIES.md wording — TASK-0026.003, after both build
    subtasks land (that task needs to see what actually shipped here vs.
    was deferred).
- Constraints And Invariants:
  - Python stdlib or POSIX shell only, no new runtime dependency.
  - `repo.vcs.staged-files` and `repo.vcs.changed-files` output must be
    sorted and stable across repeated calls against unchanged state —
    CAPABILITIES.md already promises determinism for these two.
  - `--json` must be supported on every subcommand in this slice; plain
    output should stay human-readable (not raw JSON dumped by default).
  - must not shell out to anything beyond `git` plus stdlib
    file/subprocess handling.
- Planned Validation: run each subcommand against this repo's actual
  current working tree and confirm output matches direct `git status`,
  `git diff --staged --stat`, `git diff --staged --name-only`, and `git
  diff --name-only` (plus staged) respectively — the runner must not
  disagree with git itself. Re-run twice back to back with no intervening
  change and confirm identical output (determinism check).
