## Intent Contract

- Outcome: two small, pure functions — one producing the N×N connectivity
  matrix deliverable, one producing the top-5 hit list deliverable — each
  callable on real per-target data.
- In Scope:
  - `edge_propensity_to_matrix(propensity: dict, n: int) -> np.ndarray`:
    `pathways.edge_propensity` returns `{(i, j): float}` for `i < j` only
    (undirected, confirmed via [[SEAM-0006]]'s own closed record — read
    that record and `pathways.py`'s source directly, don't re-derive the
    shape from memory). Build the symmetric dense `(n, n)` array (zero
    diagonal, `M[i,j] == M[j,i]`) the "N×N connectivity matrix"
    deliverable actually is.
  - a thin per-target call site that supplies `report.hit_list` with real
    arguments: `scores` (from whichever occupation/ranking array `.003`'s
    pipeline produces — coordinate with `.003`'s actual output shape
    before hardcoding an assumption here), `resnums` (from the loaded
    structure), and `exclude_idx` (the functional/source residues, so the
    hit list never contains a trivial self-hit, matching cell 62's
    original masking behavior `report.hit_list`'s own docstring already
    describes).
  - unit tests: `edge_propensity_to_matrix` on a small synthetic
    `edge_propensity` output (reuse `test_pathways.py`'s existing
    fixtures/helpers), asserting symmetry, zero diagonal, and that every
    `(i, j)` key's value lands in both `M[i,j]` and `M[j,i]`; the hit-list
    call site tested against a small real or synthetic per-target case.
- Out Of Scope: `pathways.edge_propensity` itself (already correct,
  VERIFIED per SEAM-0006 — do not modify); the FROZEN-gating around which
  target's scores feed into this (`.003`'s job — this subtask's functions
  take already-computed arrays, no `protocol.py` dependency, same
  "pure, ungated" discipline as `.001`).
- Constraints And Invariants: `edge_propensity_to_matrix` must not
  silently accept a malformed key (e.g. `i >= j`, or an index `>= n`) —
  raise, don't clip or ignore, matching this codebase's general
  "raise, don't repair" convention for structural invariant violations
  (e.g. `superpose.py`'s zero-mode-count handling, per
  `INVARIANCE_PROTOCOL.md`'s own Tier 1 rule: "Never select modes by
  index... raise, do not slice").
- Planned Validation: the unit tests above; downstream, `.004`'s
  end-to-end run is the real integration check.
