## Intent Contract

- Outcome: one function, e.g.
  `run_frozen_verdict(target_name, candidates_builder) -> dict`, that:
  1. Enters `protocol.frozen_context({target_name})`.
  2. Calls `protocol.select_frozen_config(candidates_builder,
     target_name)` to pick the winning operator/parameter config —
     candidate construction and scoring both happen inside the gate, per
     `select_frozen_config`'s own contract.
  3. Runs `analysis.py`'s scoring functions (`benchmark`, `ablation`,
     `quantum_vs_classical`, `apo_holo_consistency`) against the winning
     config, still inside the gate.
  4. Calls `protocol.stamp_provenance(...)` on the raw results, still
     inside the gate — the stamp must be issued here, not after exit.
  5. Exits the context, assembles via `.001`'s function, and returns the
     stamped, assembled `results` dict — ready for `report.verdict_template`
     to render as `provenance="frozen"`.
- In Scope:
  - the function above, plus a `diagnostics.classify_failure`/
    `permutation_null` call on the winning config's scores, so a target
    whose result is actually indistinguishable from chance (or worse than
    the floor) is flagged in the assembled results rather than silently
    rendered as a clean verdict — `results["_diagnosis"]` or similar,
    consumed downstream by `.004`'s report assembly.
  - unit tests, synthetic (no network): confirm the function raises
    `LeakageError` if any step inside it is made to read `target_name`'s
    holo/pocket data directly (reuse `select_frozen_config`'s own
    "poisoned builder" test pattern from `test_protocol.py`); confirm the
    returned dict's `"_frozen_stamp"` verifies true via
    `protocol.verify_frozen_stamp`; confirm it composes correctly with
    `.001`'s assembly (once that subtask lands — coordinate ordering, or
    stub the dependency if `.001` isn't done yet, per this repo's
    "narrow the first validation action" convention).
- Out Of Scope: candidate generation itself (which operator/parameter
  combinations to try) — reuse whatever mechanism `select.py`'s own tests
  already establish as a valid candidate shape (`{"H", "source", "t"}`
  dicts); this subtask does not invent a new search space, it wires the
  existing one through the gate correctly.
- Constraints And Invariants: **the single most important invariant in
  this whole task family** — nothing inside step 2-4 above may read
  `target_name`'s true holo/pocket label via any path other than what the
  gate already blocks (i.e. don't accidentally introduce a new
  leakage path while wiring this together; if a step genuinely needs
  data the gate would block, that's a design problem to surface, not
  route around).
- Planned Validation: the leak-blocking unit test above is non-negotiable
  — this subtask is not Done without it passing for real, not just "no
  test happened to trigger it."
